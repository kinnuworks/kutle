# Device side

Everything between a battery's fuel gauge and `ReadingLog`: the reading format,
the board that signs readings, the gateway that batches and anchors them, and
the station that provisions devices.

| Path | What |
|---|---|
| `SPEC.md` | Reading record, Merkle tree, digests, device keys, gateway-device protocol |
| `test-vectors.json` | Shared vectors, generated by `scripts/gen-vectors.ts`, checked by TypeScript and C |
| `lib/` | Shared TypeScript: reading, merkle, digest, keys, keystore, signer, edge protocol client, ABIs |
| `gateway/` | Samples the battery, stores readings, batches, signs, anchors, proves |
| `provision/` | Provisioning station CLI and the key ceremony (`provision/README.md`) |
| `firmware/` | ESP32-S3 firmware, its native test and host build (`firmware/README.md`) |
| `scripts/local-chain.ts` | Deploys the contracts to anvil for tests and manual runs |

The TypeScript runs directly on Node 24 or later (type stripping); there is no
build step. `pnpm typecheck` runs `tsc` with `noEmit`.

## Setup

```
cd device
pnpm install
make -C firmware/sim                 # host build of the firmware protocol
```

The gateway imports `tools/mldsa/prepare.mjs`, so `tools/` needs its
dependencies installed too (`pnpm install` in `tools/`).

## Tests

```
node --test gateway/test/                                   # unit tests, no chain
KUTLE_E2E=1 node --test gateway/test/e2e.test.ts            # anvil end to end
cd firmware && ../.venv/bin/pio test -e native              # C against the same vectors
```

The unit tests cover the ioreg parser against a captured (serials redacted)
`AppleSmartBattery` dump, the shared vectors, the digests, blob and degeneracy
floor against `contracts/test/fixtures/mldsa.json`, the keystore, and edge mode
against the firmware host build (replay guard, out-of-order readings, seed
export and lock, smbus mode with a synthetic gauge).

The end-to-end test starts anvil with the Osaka hardfork, deploys the real
contracts from `contracts/out` with the real ML-DSA-44 verifier, provisions an
edge device (the firmware host build) with the full ceremony, issues a
passport, anchors two batches, proves every reading with
`ReadingLog.verifyReading` and checks a forged leaf fails; then repeats with a
gateway-mode keystore device. Run `forge build` in `contracts/` first if
`contracts/out` is missing.

## Running the gateway

```
export RPC_URL=... READING_LOG=0x... PASSPORT_ID=1 DEVICE_ID=0x... RELAYER_KEY=0x...
export KUTLE_SIGNER=edge KUTLE_DEVICE=/dev/cu.usbmodemXXXX     # or sim:firmware/sim/build/kutle-sim <dir>
# fallback without a board:
# export KUTLE_SIGNER=gateway KUTLE_KEYSTORE=device.keystore.json KUTLE_KEYSTORE_PASSPHRASE=...

node gateway/src/cli.ts sample                    # one reading of this Mac's battery
node gateway/src/cli.ts run --interval 60 --batch 30
node gateway/src/cli.ts anchor                    # anchor whatever is pending now
node gateway/src/cli.ts prove --seq 0 --index 3   # or --wire <hex>, or --reading '<json>'
node gateway/src/cli.ts status
```

The gateway reads `nextSeq` and `lastToTs` from `ReadingLog` before every
batch, skips stored readings older than `lastToTs`, checks that the passport is
bound to the device, recomputes the root and digest itself and verifies both
signatures before sending the transaction. Data lives in `gateway/data/`
(gitignored).

Readings come from `ioreg -r -c AppleSmartBattery -a`. Field mapping is in
`SPEC.md` section 1; `fullChargeCapacity_mAh` is `AppleRawMaxCapacity` because
`MaxCapacity` is a percentage on Apple silicon Macs.

## Manual run against anvil

```
anvil --hardfork osaka &
node scripts/local-chain.ts deploy        # writes gateway/data/local-deployment.json
KUTLE_KEYSTORE_PASSPHRASE=... node provision/src/cli.ts keygen --out dev.keystore.json
RPC_URL=http://127.0.0.1:8545 DEVICE_REGISTRY=... REGISTRAR_KEY=<anvil key 0> \
  KUTLE_SIGNER=gateway KUTLE_KEYSTORE=dev.keystore.json KUTLE_KEYSTORE_PASSPHRASE=... \
  node provision/src/cli.ts register --operator <anvil address 0> --label mac-battery
node scripts/local-chain.ts issue --device-id <id printed above>
```

Measured on anvil: `registerDevice` about 1.73M gas, `anchor` about 1.46M gas
(both dominated by one ML-DSA-44 verification).
